## 前言

### 文档目的

本方案的目标是建立一个可靠的 AI 仿真实验平台，用于对卡牌游戏中的 9 个角色进行强度评估、平衡性分析与 Meta 环境监测。核心产出为：

1. **角色强度量化**：回答"角色 A 是否显著强于角色 B？"——不是凭感觉，而是由统计检验给出结论
2. **平衡性偏差定位**：识别过强/过弱角色、克制链断裂、环境单一化
3. **数据驱动的迭代闭环**：每一轮设计修改后，通过仿真验证其影响

### 设计原则

- **理论先于实现**：每个策略决策和统计方法先有形式化定义，再谈代码实现
- **统计学可靠性**：所有强度结论附带置信度、效应量和多重比较修正
- **工程可复现**：DL/RL 策略的可靠性由工程体系保障，而非统计推断

## 第一章 对局仿真引擎设计

### 1.1 仿真目标

对局仿真的根本目的是**以可控、可复现、可量化的方式模拟玩家对局行为**，从而在以下三个层面支持角色强度分析：

| 层面 | 问题 | 仿真角色 |
|------|------|---------|
| 基线层 | 没有人类数据时如何建立基准？ | 参数化规则AI提供"假想玩家"行为基线 |
| 分析层 | 如何判断角色间存在真实强度差异？ | 大量仿真局提供统计检验的样本量 |
| 设计层 | 一个改动是否改善了平衡性？ | 改动前后两次仿真的差异检验 |

### 1.2 仿真引擎架构

引擎的核心设计约束是**无状态、可重入、确定性执行**。

```
┌──────────────────────────────────────────────┐
│              GameEngine (无头引擎)              │
│  • initGame(characterIds) → 初始化游戏状态    │
│  • getState() → 返回当前 GameState            │
│  • placeEnergy(playerId, cardIndex) → void    │
│  • useSkill(playerId, skillIndex, target) → void│
│  • useSpecialCard(playerId, cardIndex) → void │
│  • advancePhase() → 推进到下一阶段/玩家       │
│  • exchangeCard(playerId, cardIndex) → void   │
│  • 状态完全封闭在实例内部，外部只能通过方法驱动 │
└──────────────────────────────────────────────┘
                          ▲
                          │ 调用
┌──────────────────────────────────────────────┐
│          IPlayerPolicy (策略接口)              │
│  • decide(state, playerId) → Action           │
│     Action = PlaceEnergy | UseSkill |         │
│              UseSpecialCard | Exchange | Pass │
└──────────────────────────────────────────────┘
                          ▲
                          │ 实现
┌──────────────────────────────────────────────┐
│  RandomAI      RuleBasedAI    [未来:RLAgent] │
│  (随机基线)    (参数化策略族)                 │
└──────────────────────────────────────────────┘
```

关键设计点：

1. **无状态**：引擎不持有外部状态引用（无 DOM、无网络、无持久化依赖），所有输入通过方法参数传递，输出通过返回值反映
2. **可重入**：同一策略实例可以顺序参与多局对战，局间通过 `initGame()` 完全重置
3. **确定性**：在固定随机种子下，相同的决策序列必然产生相同的结果序列。引擎内部的所有随机性（洗牌、抽牌）必须通过可注入的 PRNG（伪随机数生成器）实现

### 1.3 并发调度策略

#### 1.3.1 任务模型

角色强度分析的最小统计单元是**一场 1v1 对局**。给定角色集合 $C = \{c_1, c_2, \dots, c_9\}$，每一对 $(c_i, c_j)$ 构成一个"对局组合"。

对于 9 个角色，不区分先后手（每个组合运行双向对局）的组合数为：

$$\binom{9}{2} = 36$$

每个组合需运行 $n$ 场对局（$n$ 由统计精度要求决定，见第四章），总对局数 $N = 36n$。

#### 1.3.2 调度架构

```
调度器                            Worker 池
┌─────────────┐            ┌──────────────────┐
│ 任务队列     │ ──分配──→  │ Worker 1          │
│ (cᵢ,cⱼ) × n │            │ GameEngine + Policy│
│             │            ├──────────────────┤
│ 结果聚合器   │ ←──回收──  │ Worker 2          │
│ 写入存储     │            │ GameEngine + Policy│
└─────────────┘            ├──────────────────┤
                           │ ...               │
                           └──────────────────┘
```

池化策略：

- **串行（单线程）**：最可靠，不存在竞争条件，适合调试和小规模验证。吞吐量约 10-50 局/秒
- **多 Worker 并行**：每 Worker 拥有独立的 GameEngine 实例和策略实例，通过进程间通信（IPC）仅传递启动参数和最终结果。适合大规模批量采集

关键约束：**Worker 之间必须完全隔离**，不允许共享任何可变状态，防止并发污染对局结果。

#### 1.3.3 超时与熔断

- 每场对局设置最大回合数 $T_{max}$（如 100 回合），超出则判定为平局并标记
- 单个对局设置最大 wall-clock 时间（如 30s），超出则终止该 Worker
- 当某角色组合的异常终止率 > 5%，该组合结果应标记为不可信

### 1.4 引擎可靠性保障

引擎级别的可靠性通过以下机制确保：

1. **物理时间隔离**：对局计时使用单调时钟（monotonic clock），不受系统时间调整影响
2. **状态隔离**：每场对局使用独立的 engine 实例，结束后完全销毁，不残留任何状态
3. **对局间无副作用**：策略实例可以复用，但每次 `decide()` 调用应仅依赖 `state` 参数，不依赖内部缓存

### 1.5 牌堆初始化与随机性管理

仿真引擎必须精确复现真人对局中的牌堆行为，同时保证可复现性。

#### 1.5.1 牌堆构成

牌堆严格按游戏规约的概率分布生成固定数量的卡牌：

| 卡牌类型 | 出现概率 | 单副牌数量（60张基准） |
|----------|---------|:-------------------:|
| 1能量卡 | 40% | 24 |
| 2能量卡 | 30% | 18 |
| 3能量卡 | 15% | 9 |
| 万能能量卡 | 5% | 3 |
| 特殊卡（16种均分） | 10% | 6（每种0-1张） |

#### 1.5.2 伪随机数生成器（PRNG）

所有随机事件（洗牌、抽卡、万能能量实际值随机等）由统一的 PRNG 驱动。

**种子派生规则**：

```
实验种子 seed_experiment（一次实验手工指定，记录在实验清单中）
    │
    ├── 对局 0: seed_match_0 = SHA256(seed_experiment || 0 || "match")
    ├── 对局 1: seed_match_1 = SHA256(seed_experiment || 1 || "match")
    ├── ...
    └── 对局 k: seed_match_k = SHA256(seed_experiment || k || "match")
```

- 不同 match_index → 不同牌序 → **统计独立性**
- 相同 seed_experiment + 相同 match_index → **完全可复现**
- seed_match 记录在 Replay 的 `seed` 字段

**推荐 PRNG 实现**：xoshiro256** 或 PCG 系列——通过 BigCrush 统计测试，周期 ≥ 2²⁵⁶，适合大规模并发场景。也可选择 Node.js 原生 `crypto.randomInt()` 或确定性版本 `seedrandom` 库。

#### 1.5.3 抽卡流程

```
1. 开局: 牌堆按 seed_match 做 Fisher-Yates 洗牌 → 每人抽 4 张
2. 换牌: 放回底部的卡不入弃牌区，换牌后整副牌再次 Fisher-Yates 洗牌
3. 阶段2: 每轮行动开始时从牌堆顶部抽 2 张（计入回合抽牌限制）
4. 牌堆耗尽: handleDeckDepletion() 回收弃牌区 → Fisher-Yates 洗牌 → 新牌堆
5. 特殊卡抽到后进入手牌，使用规则与游戏规约完全一致
```

#### 1.5.4 复现验证

每个 Batch 采集完成后，抽取 0.1% 对局用记录的 seed 重新跑一次，验证结果完全一致。若存在不一致则该 Batch 标记为"不可信"并重新采集。

## 第二章 规则AI策略体系

### 2.1 设计哲学：参数化策略族

规则 AI 的角色不是"写一个聪明的 AI"，而是**构造一组行为参数可调的"假想玩家"，作为统计分析中的可控变量**。

单一固定策略无法区分"角色强"和"这个策略恰好适合这个角色"——因此我们需要的是一个策略族 $\mathcal{P}$，其成员通过超参数 $\theta$ 区分：

$$\mathcal{P} = \{P(\theta) \mid \theta \in \Theta\}$$

通过运行多个策略变体，可以将角色强度测量中的"策略偏差"量化并分离。

### 2.2 策略接口与决策树

每个策略 $P(\theta)$ 的核心是一个**条件决策树**：给定当前游戏状态 $s$，策略输出一个动作 $a$。

```
决策树结构（形式化描述）：

Phase: card_exchange
    ├─ 如果 remaining_exchanges > 0:
    │   ├─ 手牌中有 <2能量卡 → 替换最低能量卡
    │   └─ 手牌全 ≥2能量卡 → 替换万能能量卡（如有）或 pass
    └─ 如果 remaining_exchanges = 0 → pass

Phase: phase1 (能量放置)
    └─ 选择一张能量卡放置（策略参数决定选择规则）
        └─ 确认放置 → advancePhase

Phase: phase2 (行动)
    ├─ 检查可用技能列表（能量充足 + 未达上限）
    │   ├─ 技能优先级队列（由 θ 决定）→ 选择最高优先级技能
    │   │   └─ 选择目标（由 θ 决定的目标效用函数）→ 支付能量 → 使用
    │   └─ 无可用技能 → 使用特殊卡（如有）
    └─ 无可用行动 → pass → advancePhase
```

### 2.3 参数空间定义

策略 $P(\theta)$ 的超参数空间 $\Theta$ 定义如下：

| 参数名 | 符号 | 类型 | 范围 | 说明 |
|--------|------|------|------|------|
| 行动顺序权重 | $\theta_{priority}$ | 连续 | [0, 1] | 在 phase1 决定是否放置能量卡抢行动顺序：0 = 优先保留高能量卡给技能（放最低能量卡"保底"），1 = 优先抢先行动（放最高能量卡） |
| 万能能量策略 | $\theta_{wild}$ | 枚举 | keep/place/bal | 对万能能量卡的处理方式：keep=始终保留用于技能，place=始终放置用于抢顺序，bal=视当前手牌情况动态决策（注意：抢顺序时万能能量卡视为 1 能量，因此该参数效果可能不显著，需实证后决定保留或裁剪） |
| HP 危险阈值 | $\theta_{hp\_danger}$ | 连续 | [0.2, 0.5] | 当前 HP/最大 HP 低于此值则优先回复/护盾 |
| 进攻倾向 | $\theta_{aggro}$ | 连续 | [0, 1] | 目标选择中伤害权重 vs 防御权重 |
| 印记感知系数 | $\theta_{mark\_weight}$ | 连续 | [0, 2] | 目标身上负面印记对目标选择的加权 |
| 技能偏好向量 | $\theta_{skill\_pref}$ | 多维 | [0,1]⁴ | 4个技能的相对优先级权重 |
| 特殊卡使用阈值 | $\theta_{special\_threshold}$ | 连续 | [0, 1] | 血量低于此比例时使用回复类特殊卡 |
| 随机扰动 | $\theta_{noise}$ | 连续 | [0, 0.2] | 决策时以 $\theta_{noise}$ 概率随机选择而非最优（用于模拟人类失误） |

典型策略配置（示例）：

| 配置名称 | 说明 | $\theta_{priority}$ | $\theta_{aggro}$ | $\theta_{hp\_danger}$ | $\theta_{skill\_pref}$ | 其他 |
|----------|------|:---:|:---:|:---:|:---:|:---:|
| 激进 | 低血量也优先输出，抢先行动 | 0.8 | 0.9 | 0.25 | [0.15, 0.05, 0.4, 0.4] | $\theta_{wild}=place$ |
| 保守 | 血量安全才进攻，留能量 | 0.2 | 0.3 | 0.40 | [0.1, 0.4, 0.3, 0.2] | $\theta_{wild}=keep$ |
| 均衡 | 平衡攻防，动态决策 | 0.5 | 0.5 | 0.35 | [0.25, 0.25, 0.25, 0.25] | $\theta_{wild}=bal$ |
| 控场 | 注重印记控制 | 0.4 | 0.4 | 0.30 | [0.2, 0.1, 0.5, 0.2] | $\theta_{mark\_weight}=1.5$ |

### 2.4 能量放置策略

**目标**：在"先行动"的优势与"保留高能量卡给技能"的收益之间做权衡。

**形式化**：在 phase1 中，玩家 $p$ 放置一张能量值为 $e$ 的卡。放置的边际收益函数为：

$$U_{place}(e) = w_1 \cdot f_{priority}(e) + w_2 \cdot g_{opportunity}(e)$$

其中：
- $f_{priority}(e)$ 为"先行动带来的收益"，取决于当前手牌中能量卡分布和预期对手行动
- $g_{opportunity}(e)$ 为"保留此卡用于技能的损失"，取决于技能消耗需求
- $w_1, w_2$ 为 $\theta$ 中的权重参数

**简化实现**：采用加权评分策略。对每张手牌中的能量卡 $e$ 计算放置评分：

$$S_{place}(e) = \theta_{priority} \cdot \frac{e}{3} \;-\; (1 - \theta_{priority}) \cdot \frac{min(e, max\_skill\_cost)}{max\_skill\_cost}$$

- 第一项：放此卡去抢行动顺序的收益（归一化到 [0,1]，能量越高的卡放置后行动顺序越靠前）
- 第二项：保留此卡用于技能的收益损失（被技能消耗吸收的部分）
- 选择 $S_{place}(e)$ 最高的卡放置，若所有卡评分均为负则放置最低能量的卡

**行为对照**：
- $\theta_{priority} = 0$：从不放置（除非强制），全部能量卡留作技能资源
- $\theta_{priority} = 0.3$：仅放置 1 能量卡，保留 2/3 能量卡
- $\theta_{priority} = 0.7$：放置 1/2 能量卡，保留 3 能量卡
- $\theta_{priority} = 1$：放置手中最高能量的卡，一切以先行动为目标

### 2.5 目标选择建模

目标选择通过**效用函数** $U_{target}(p_i, p_j)$ 决定，$p_i$ 为当前决策玩家，$p_j$ 为候选目标：

$$U_{target}(p_i, p_j) = \alpha_{aggro} \cdot D(p_j) + (1 - \alpha_{aggro}) \cdot V(p_j) + \beta \cdot M(p_j)$$

其中：
- $D(p_j) = 1 - \frac{hp_j}{hp_{max\_j}}$：目标血量缺失程度（残血补刀价值）
- $V(p_j)$：目标的"威胁度"，由目标技能消耗总和 / 目标手牌能量估算值表征
- $M(p_j)$：目标身上的负面印记密度（$\sum$负面印记剩余回合 / 3）
- $\alpha_{aggro} \in [0, 1]$ 由策略的进攻倾向参数控制
- $\beta$ 由印记感知系数 $\theta_{mark\_weight}$ 控制

**注意**：效用函数给出的只是**优先级排序**，并非对效果保真度的承诺。效用函数的目的是使不同策略变体的行为差异可理解和可复现，而非复刻人类决策的复杂性。

### 2.6 技能优先级排序

每个技能 $k$ 的"期望收益"定义为：

$$E[reward_k] = damage_k + heal_k + mark\_value_k - opportunity\_cost_k$$

其中各分量计算方法：
- $damage_k$：技能描述中的直接伤害 + 穿透数值
- $heal_k$：回复量（若有）
- $mark\_value_k$：附加的各印记的加权价值（每个正面印记 +2，每个负面印记计为施加于对手的 +2）
- $opportunity\_cost_k$：消耗的能量值可被其他技能使用的折损

策略在每轮行动时按照 $E[reward_k]$ 降序尝试技能，直到能量不足以支付或达到回合使用上限。

### 2.7 策略多样性保证

单一策略无法覆盖角色强度的全貌。多样性通过以下方式保证：

1. **参数网格扫描**：在 $\Theta$ 空间中选取 $m$ 个代表性配置点，$m$ 与参数维度成正比（建议 $m \geq 8$）
2. **策略池执行**：每对 $(c_i, c_j)$ 使用多组策略配置分别运行，结果为策略-角色混合效应的观测
3. **方差分解**：角色 $c_i$ 对战角色 $c_j$ 的总方差分解为：

$$\sigma^2_{total} = \sigma^2_{character} + \sigma^2_{strategy} + \sigma^2_{noise}$$

通过此分解可以识别：角色间的强度差异是否在策略变化下保持稳定（即 $\sigma^2_{character} \gg \sigma^2_{strategy}$）。

### 2.8 超参数优化：从经验到数据驱动

2.3 节定义的参数空间 $\Theta$ 目前依赖于经验和主观判断来设定。本方案要求最终的参数标定应通过**数据驱动**的方式完成，以下是三种可行的优化路径：

#### 2.8.1 贝叶斯优化（推荐）

将策略胜率 $f(\theta)$ 视为黑箱函数，观测值因 Bernoulli 试验本质携带噪声。

**原理**：
- 使用**高斯过程（Gaussian Process, GP）** 对 $f(\theta)$ 建模，GP 的预测同时给出均值 $\mu(\theta)$ 和不确定性 $\sigma(\theta)$
- 每轮评估一个参数点后，GP 更新后验分布
- 下一轮使用**采集函数（Acquisition Function）** 选择最有"信息价值"的点

常用采集函数：

$$\text{EI}(\theta) = \mathbb{E}[\max(f(\theta) - f^*, 0)] \quad \text{(Expected Improvement)}$$

$$\text{UCB}(\theta) = \mu(\theta) + \kappa \cdot \sigma(\theta) \quad \text{(Upper Confidence Bound)}$$

**流程**：
```
1. 在 Θ 上均匀采样 10-20 个初始点
2. 每个点运行 n 局对局（n 由 Power Analysis 确定），记录平均胜率
3. 用现有观测拟合 GP 模型
4. 采集函数推荐下一个参数点
5. 评估新点 → 更新 GP → 重复直到收敛或达到预算上限
```

**收敛判据**：连续 10 轮推荐点的 $\mu(\theta) \pm 1.96\sigma(\theta)$ 置信区间与当前最优点的置信区间重叠，或优化轮数达到预设上限（建议 100 轮）。

**优势**：样本效率高（~100-300 次评估即可收敛），天然给出参数不确定性估计。

#### 2.8.2 带统计检验的网格搜索（实现成本最低）

若不想引入贝叶斯方法的实现复杂度：

- 对每个连续参数离散化为 $k$ 个水平（建议 $k=5$：等分区间）
- 对 $\theta_{skill\_pref}$ 使用单纯形格点设计（Simplex Lattice Design），确保 $\sum \theta_{skill\_pref} = 1$
- 总网格点数为各参数水平数的乘积，实际可通过**部分因子设计**（Fractional Factorial Design）降低至 $\sim 10^2$
- 用 **ANOVA** 识别各参数主效应和交互效应，用 **Kruskal-Wallis** 做非参数检验

#### 2.8.3 CMA-ES（高维参数空间）

**CMA-ES（Covariance Matrix Adaptation Evolution Strategy）** 是一种无梯度进化优化算法：

- 在每个迭代步，从当前多元正态分布 $\mathcal{N}(m_t, \sigma_t^2 C_t)$ 中采样 $\lambda$ 个参数点
- 用表现最好的前 $\mu$ 个点更新分布的均值 $m_t$ 和协方差矩阵 $C_t$
- 协方差矩阵的更新等价于**学习参数的二阶交互关系**
- 对噪声鲁棒，适合 $>10$ 维参数空间

**优势**：不需要对 $f(\theta)$ 做概率建模假设；劣势：样本效率低于贝叶斯优化。

#### 2.8.4 本方案推荐路径

| 阶段 | 方法 | 原因 |
|------|------|------|
| 2.0.0 初期 | 手工定义 8-12 组有语义的策略配置（覆盖 $\Theta$ 空间） | 快速启动，验证管线 |
| 2.0.0 精调 | 贝叶斯优化对关键参数（$\theta_{aggro}, \theta_{priority}, \theta_{hp\_danger}$）精调 | 平衡效率与实现成本 |
| 2.1.0+ | 全参数空间贝叶斯优化 + 角色独立优化 | 为方案C 做准备 |

### 2.9 策略-角色绑定架构

Meta 分析所使用的策略与角色之间的关系，直接影响强度评估的结论，需要谨慎设计。

#### 2.9.1 三种架构方案

**方案A：策略与角色解耦（独立测量）**

所有角色在仿真中使用**同一组**策略参数 $\Theta_{generic}$。

$$胜率(c_i, c_j) \Big|_{\theta_{generic}}$$

- **测量目标**：给定相同的决策框架，角色本身的固有强度差异
- **因果清晰**：任何观测到的胜率差异都归因于角色设计，而非策略适应
- **缺陷**：忽略了一个角色的"强度"部分取决于它被如何操作

**方案B：策略与角色完全绑定（角色特化）**

每个角色 $c_i$ 拥有**独立优化**的策略参数 $\theta_i^*$：

$$\theta_i^* = \arg\max_{\theta \in \Theta} \text{win\_rate}(\theta, c_i)$$

$$胜率(c_i, c_j) \Big|_{\theta_i^*, \theta_j^*}$$

- **测量目标**：每个角色在**最优操作**下的天花板强度
- **更接近真实对战**：反映 Meta 环境中玩家会逐渐找到每个角色的最优打法
- **缺陷**：无法区分"角色强"还是"角色刚好容易优化"；需要额外优化成本

**方案C：混合解耦（推荐最终方案）**

两阶段测量，分别回答两个不同的问题：

**第一阶段** —— 通用强度（Base Strength）：

所有角色使用同一套基础策略 $\theta_{generic}$，得到 $R_{base}(c_i)$。

**第二阶段** —— 有效强度（Effective Strength）：

为每个角色独立做超参数优化（2.8 节方法），得到 $\theta_i^*$，然后用 $\{\theta_i^*\}$ 跑全矩阵：

$$胜率(c_i, c_j) \Big|_{\theta_i^*, \theta_j^*}$$

得到 $R_{effective}(c_i)$。

**第三阶段** —— 操作天花板分析：

$$\Delta(c_i) = R_{effective}(c_i) - R_{base}(c_i)$$

$\Delta(c_i)$ 的解释：
- $\Delta$ 大（如 $>50$ Elo）：该角色潜力高但难用好
- $\Delta$ 小（如 $<10$ Elo）：该角色操作空间有限，强度几乎完全由设计决定
- $\Delta$ 为负：该角色的"直觉打法"可能比优化打法更好（即规则 AI 天然适配该角色）

#### 2.9.2 本方案实施策略

```
当前阶段 (2.0.0): 方案A
    ↓
    - 先跑通全管线（引擎 → 采集 → 分析 → 报告）
    - 验证 GameEngine 正确性、策略多样性、统计方法的有效性
    
过渡阶段 (2.1.0 中期): 方案A + 角色最优 θ 探索
    ↓
    - 对每个角色独立运行超参数优化（贝叶斯优化）
    - 比较 Δ(c_i) 分布，判断操作天花板是否显著
    
最终阶段 (2.2.0): 方案C 全量实施
    ↓
    - 方案A 结果作为基线，方案C 结果作为有效强度
    - 两份报告对比输出，标注 Δ(c_i) 差异
```

## 第四章 Meta分析与角色强度评估

### 4.1 角色胜率矩阵

#### 4.1.1 基础定义

对于角色集合 $C = \{c_1, \dots, c_9\}$，定义 $W_{ij}$ 为角色 $c_i$ 对 $c_j$ 的胜率。每局 $c_i$ vs $c_j$ 的结果 $X$ 是一个 Bernoulli 随机变量：

$$X_{ijk} \sim \text{Bernoulli}(p_{ij}), \quad k = 1, \dots, n$$

其中 $X_{ijk} = 1$ 表示 $c_i$ 胜。$p_{ij}$ 为 $c_i$ 对 $c_j$ 的真实胜率。

观测胜率为：

$$\hat{p}_{ij} = \frac{1}{n} \sum_{k=1}^n X_{ijk}$$

#### 4.1.2 置信区间

$\hat{p}_{ij}$ 的 $100(1-\alpha)\%$ Wilson 置信区间：

$$\frac{\hat{p}_{ij} + \frac{z_{\alpha/2}^2}{2n}}{1 + \frac{z_{\alpha/2}^2}{n}} \pm \frac{z_{\alpha/2}}{1 + \frac{z_{\alpha/2}^2}{n}} \sqrt{\frac{\hat{p}_{ij}(1-\hat{p}_{ij})}{n} + \frac{z_{\alpha/2}^2}{4n^2}}$$

其中 $z_{\alpha/2}$ 是标准正态分布的双侧临界值（$\alpha=0.05$ 时 $z \approx 1.96$）。

Wilson 区间优于正态近似区间，因为它在 $\hat{p}$ 接近 0 或 1 时不会越界。

### 4.2 样本量确定（Power Analysis）

在实验设计阶段，需要确定最小样本量 $n_{min}$。对于双比例 Z 检验，给定：

- 显著性水平 $\alpha$（通常 0.05）
- 统计功效 $1-\beta$（通常 0.80）
- 最小可检测效应量 $d = |p_1 - p_2|$

每组所需样本量（每组局数）：

$$n = \frac{(z_{\alpha/2} + z_{\beta})^2 \cdot 2\bar{p}(1-\bar{p})}{d^2}$$

其中 $\bar{p} = (p_1 + p_2)/2$。

**示例计算**（$\alpha=0.05$, $1-\beta=0.80$, $z_{\alpha/2}=1.96$, $z_{\beta}=0.842$）：

| 期望检测到的胜率差异 $d$ | 每组所需对局数 $n$ |
|:---:|:---:|
| 5%（如 52.5% vs 47.5%） | ≈ 1570 |
| 10%（如 55% vs 45%） | ≈ 392 |
| 15%（如 57.5% vs 42.5%） | ≈ 174 |
| 20%（如 60% vs 40%） | ≈ 98 |

> **说明**：样本量估算的目的是在设计阶段确认资源投入的合理性。实际运行中应使用比 $n_{min}$ 多 20-30% 的局数以弥补异常终止和无效对局的损耗。

### 4.3 假设检验

#### 4.3.1 双比例 Z 检验

检验角色 $c_i$ 对 $c_j$ 的胜率是否显著偏离 50%（即 $H_0: p_{ij} = 0.5$）：

$$Z = \frac{\hat{p}_{ij} - 0.5}{\sqrt{0.5 \times 0.5 / n}}$$

若 $|Z| > z_{\alpha/2}$，拒绝 $H_0$，差异显著。

#### 4.3.2 Fisher 精确检验

当 $n$ 较小时（< 30），或期望频数 $\hat{p}_{ij}n < 5$ 时，应使用 Fisher 精确检验替代 Z 检验，因为此时正态近似不可靠。

### 4.4 多重比较修正

当同时检验 $\binom{9}{2} = 36$ 对角色的胜率时，**多重比较问题**不可忽略：在 $\alpha = 0.05$ 下，即使所有角色强度相同，预期也会有 $36 \times 0.05 \approx 2$ 个"显著的"假阳性结果。

#### 4.4.1 Bonferroni 修正

最保守的修正：将单个检验的显著性阈值调整为 $\alpha / m$。

$$\alpha_{Bonferroni} = \frac{\alpha}{m} = \frac{0.05}{36} \approx 0.00139$$

**代价**：当 $m$ 较大时，统计功效（power）显著降低，可能导致真正存在的差异无法被检出。

#### 4.4.2 Benjamini-Hochberg FDR 修正

控制**错误发现率（False Discovery Rate, FDR）**，即所有拒绝中假阳性比例不超过 $q$（常用 $q = 0.05, 0.10$）。

步骤：
1. 对 36 个检验的 p-value 从小到大排序：$p_{(1)} \leq p_{(2)} \leq \dots \leq p_{(36)}$
2. 找到最大的 $k$ 使得 $p_{(k)} \leq \frac{k}{m} \cdot q$
3. 拒绝 $H_0^{(1)}, H_0^{(2)}, \dots, H_0^{(k)}$

FDR 的敏感度高于 Bonferroni，在本场景（需要发现但不希望误报）中更为推荐。

**建议的执行策略**：同时输出两种修正结果，当两者结论一致时置信度更高，不一致时以 FDR 为主，标记为"需更多数据确认"。

### 4.5 效应量度量

显著性检验回答"是否存在差异"，效应量回答"差异有多大"——后者在平衡性分析中更为重要。

#### 4.5.1 Cohen's h

用于比例差异的效应量指标：

$$h = 2 \cdot \arcsin(\sqrt{p_{ij}}) - 2 \cdot \arcsin(\sqrt{0.5})$$

| $h$ 值 | 解释 |
|:---:|------|
| 0.0 - 0.2 | 可忽略 |
| 0.2 - 0.5 | 小效应 |
| 0.5 - 0.8 | 中效应 |
| > 0.8 | 大效应 |

对于卡牌游戏平衡性，**小效应（$h > 0.2$）应当引起关注，中效应（$h > 0.5$）应视为需要调整**。

#### 4.5.2 AUC（Area Under Curve）

AUC 的值等于：随机抽取一场 c_i vs c_j 的对局，c_i 获胜的概率。在 1v1 场景下，AUC = $p_{ij}$，可以直接解读。

### 4.6 评级系统建模

胜率矩阵是"静态"的（每对角色分别统计），而评级系统是"动态"的（从所有对局数据中联合估计每个角色的强度参数）。

#### 4.6.1 Elo 评级

经典 Elo 系统的基本公式：

$$E_{ij} = \frac{1}{1 + 10^{(R_j - R_i) / 400}}$$

其中 $E_{ij}$ 为角色 $c_i$ 对 $c_j$ 的期望得分，$R_i$ 和 $R_j$ 为评级分。

对局后评级更新：

$$R_i' = R_i + K \cdot (S_i - E_{ij})$$

其中 $S_i \in \{0, 0.5, 1\}$ 为实际得分，$K$ 为权重因子。

**Elo 在本场景的优势**：
- 所有对局数据共同参与评级，比独立胜率更稳定
- 即使某些组合对局数不平衡，也能给出合理估计
- 评级差可直接换算为期望胜率：$R_i - R_j = 100$ 意味着 $c_i$ 有约 64% 胜率预期

**Elo 的限制**：
- 假定强度是单一维度的，不支持克制关系（若 $c_i$ 克制 $c_j$ 但被 $c_k$ 克制，Elo 会给出一个折中评级，无法表现三角关系）
- 因此 Elo 应与胜率矩阵配合使用，而非替代

#### 4.6.2 Glicko 评级

Glicko 系统在 Elo 的基础上增加了**评级置信度（Rating Deviation, RD）**，衡量评级的可靠程度：

- 新角色初始 RD 较高（评级不可靠）
- 随着对局数增加，RD 下降（评级趋稳）
- 长时间不参与对局，RD 回升（评级变过时）

这对于鉴别"数据不足"的假性结论特别有用——一个角色如果只对战了少数组合但有较高胜率，其 RD 会反映这一不确定性。

### 4.7 克制关系图

#### 4.7.1 定义

克制关系通过**胜率偏离随机期望的幅度**来度量。角色 $c_i$ 对 $c_j$ 的克制强度定义为：

$$K_{ij} = \hat{p}_{ij} - 0.5$$

范围 $[-0.5, 0.5]$，正值表示 $c_i$ 克制 $c_j$。

#### 4.7.2 Bootstrap 置信度

对克制边 $K_{ij}$ 的置信度通过 Bootstrap 方法计算：

1. 从原始 $n$ 场对局中有放回重采样 $B$ 次（$B \geq 1000$）
2. 每次计算 $K_{ij}^{(b)}$
3. 从 $B$ 个 $K_{ij}^{(b)}$ 构建 $95\%$ 百分位置信区间
4. 若置信区间不包含 0，则该克制关系在统计上显著

#### 4.7.3 图谱可视化

克制关系图为一个**有向加权图**：
- 节点 = 角色
- 有向边 $c_i \to c_j$ 权重 = $K_{ij}$（仅当 $K_{ij}$ 显著）
- 边透明度 = 置信度 = Bootstrap 区间远离 0 的程度

**关键指标**：
- **出度**（克制多少角色）：显示角色压制力
- **入度**（被多少角色克制）：显示角色容易被针对的程度
- **克制循环检测**：$c_i \to c_j \to c_k \to c_i$ 的循环是否存在？若存在，说明克制链健康，环境有策略深度

### 4.8 Tier 划分

#### 4.8.1 基于评分+置信度重叠的分级

Tier 划分的原则：**同一 Tier 内的角色在统计上不可区分**。

方法：
1. 使用 Elo 或 Glicko 计算每个角色的强度评分 $\hat{R}_i$ 及其标准误 $SE_i$
2. 构造每个角色的置信区间：$\hat{R}_i \pm z_{\alpha/2} \cdot SE_i$
3. 若两个角色的置信区间重叠，则它们属于同一 Tier
4. 从区间不重叠的相邻组中确定 Tier 边界

#### 4.8.2 报告的标准化输出格式

```
Tier 报告示例
═══════════════════════════════════════════
Tier S (评分 > 1600)
  char_3 (进攻)     Elo=1652±42  胜率对全角色平均: 58.2%
  
Tier A (评分 1500-1600)
  char_9 (连击)     Elo=1558±38  胜率对全角色平均: 52.8%
  char_7 (弱化)     Elo=1532±45  胜率对全角色平均: 51.5%

Tier B (评分 1400-1500)
  char_1 (平衡)     Elo=1485±35  胜率对全角色平均: 49.2%
  ...

Tier C (评分 < 1400)
  char_2 (防御)     Elo=1350±40  胜率对全角色平均: 43.1%
═══════════════════════════════════════════
置信区间重叠判定: Tier A/B 边界 p = 0.12 (未显著分离)
```

## 第五章 深度学习与强化学习策略

> **原则声明**：当决策策略从规则模型切换为学习型模型时，可靠性的关注点从"统计推断"转向"工程体系"。因为学习型策略的对局样本量通常远超统计检验所需，置信区间极窄，此时真正的问题是：**"这个策略是否真的学到了我们想要的东西？"**——这由工程体系保障，而非统计工具。

### 5.1 可复现性保障

可复现性是学习型策略可靠性的**最低保障**，没有可复现性就没有可信度。

| 维度 | 要求 | 实现方式 |
|------|------|---------|
| 随机性控制 | 所有随机源（引擎洗牌、策略探索、网络初始化）使用可注入的 Seed | Seed 从 Replay 记录中传入，确保对局可完全复现 |
| 确定性运算 | 训练和推理使用确定性算法（禁用非确定性操作如 `atomicAdd`） | CUDA `torch.backends.cudnn.deterministic = True` |
| 环境封闭 | 推理时状态空间完全由 GameEngine 定义，不依赖外部服务 | 引擎本身无外部依赖，已在 1.2 节保证 |
| 版本绑定 | 策略权重文件绑定 GameEngine 版本 hash | 加载时校验版本一致性，不一致则拒绝加载 |

### 5.2 训练监控体系

训练过程中的可靠性通过多维指标的实时监控来保证。

#### 5.2.1 核心指标

| 指标 | 含义 | 异常信号 |
|------|------|---------|
| 奖励曲线（Reward） | 每局累计奖励 | 不收敛 / 断崖下降 → 奖励设计问题 |
| 策略熵（Policy Entropy） | 策略输出的随机性 | 过低 → 过早收敛/确定性策略；过高 → 未学到 |
| KL 散度（KL Divergence） | 新旧策略差异（PPO） | 过大 → 更新步长过大；过小 → 更新无效 |
| Value Loss | 价值网络损失 | 发散 → 状态价值估计不正确 |
| 回合长度 | 对局回合数 | 异常增加 → 策略变得保守/不敢终结对局 |
| 自博弈胜率 | 当前策略 vs 自身历史冻结版本 | 不提升 → 策略未在进步 |

#### 5.2.2 异常检测

- 对每个指标设定阈值报警（如：连续 10 个 episode 奖励 < 基线的一半）
- 训练暂停时自动保存完整 Checkpoint（包含模型权重、优化器状态、训练步数）
- Checkpoint 自动过期策略：只保留最近的 N 个 + 每隔 N 步的"里程碑"版本

### 5.3 评估协议

训练阶段和评估阶段必须严格分离，防止**评估数据泄露**（即评估结果间接参与训练决策）。

#### 5.3.1 对手池设计

```
评估对手池（固定，更新频率 ≤ 1次/周）：
├── RandomAI（随机决策）→ 评估策略的绝对下限
├── 规则AI基线（3-5个典型策略变体）→ 评估跨策略稳定性
├── 历史快照（冻结的上一版本 RL 策略）→ 评估迭代进步
└── 当前策略自身（自博弈）→ 评估过拟合程度
```

#### 5.3.2 评估指标

- **对战各对手的综合胜率**（主要指标）
- **胜率分布**（使用 Bootstrap 置信区间，方法同 4.7.2）
- **策略多样性评分**：评估在面对不同对手时策略行为是否多样化（高分 = 适应性强）

#### 5.3.3 评估隔离

- 评估使用独立于训练的随机种子
- 评估期间禁用探索（exploration noise = 0）
- 评估结果仅用于报告和决策，不参与梯度计算

### 5.4 过拟合与分布偏移检测

#### 5.4.1 对手过拟合

对手过拟合表现为：策略在与训练对手池某一成员的对抗中表现异常高，但在面对新对手时表现下降。

**检测方法**：
- 在评估池中加入"新奇"对手（如随机参数的规则 AI 变体），持续监测胜率
- 若训练对手胜率 ↑ 而新奇对手胜率 ↓，说明策略特化了

#### 5.4.2 分布偏移

自博弈训练中，策略分布会随时间偏移。检测：

- **固定探针（Probe）**：保留一组固定参数的规则 AI，每次评估时与其对战
- 若策略对探针胜率**下降**，说明策略偏移到了探针不擅长的"生态位"，这是一个危险信号
- 需要引入多样性奖励（见 5.5）来对抗收敛到窄分布

### 5.5 消融实验设计

每个新增设计选择都应通过消融实验（Ablation Study）进行归因验证：

```
实验框架：
  Base (基线)        = 引擎 + 简单奖励 + 默认超参数
  +RewardShape       = Base + 奖励塑形（回合奖励/印记奖励等）  
  +NetworkDepth      = RewardShape + 更深的价值网络
  +EntropyBonus      = RewardShape + 熵正则项
  +SelfPlayHistory   = RewardShape + 历史策略回放池
```

每个消融实验评估 $k$ 次（$k \geq 5$），报告均值与标准差。

**结论判定**：若一个设计选择在被移除后性能下降超过效应量的阈值（如 Cohen's d > 0.2），则确认该选择有效；否则，应被删除以降低复杂度。

### 5.6 资源效率分析

DL/RL 策略的"可靠性"还包括：资源投入与收益是否合理。

关键分析维度：

| 维度 | 评估方法 |
|------|---------|
| 计算预算收敛曲线 | 横轴 = 总训练步数/总仿真局数，纵轴 = 评估胜率。观察曲线何时进入平台期 |
| 性价比分析 | 规则AI开发成本 vs RL 开发成本 vs 带来的额外胜率提升 |
| 边际收益递减点 | 训练到什么程度继续投入不再产生有意义的变化？ |

> **结论预期**：对于当前的 9 角色卡牌游戏，规则 AI 很可能在测量角色强度方面已经足够。DL/RL 的价值不在于"更准确的角色强度分析"，而在于探索**策略边界**——发现规则 AI 无法覆盖的盲区。因此 2.2.0+ 阶段是否采用 DL/RL，应取决于规则 AI 是否已无法区分角色差异（即所有角色 $\hat{p}_{ij} \approx 0.5$），而非先验决定。

## 第六章 渐进式质量提升路线

### 6.1 当前状态定位

| 版本 | 目标 | 实现载体 | 策略绑定架构 | 状态 |
|------|------|---------|:-----------:|------|

### 6.2 2.0.0 阶段：引擎重构 + 规则AI基线（方案A）

**策略绑定架构**：采用方案A——所有角色使用同一套通用策略参数。

**关键任务**：

1. **引擎重构**：基于 1.2 节设计原则，重写无状态、可注入 PRNG 的 GameEngine

3. **策略族实现**：基于 2.3 节参数空间，手工定义 8-12 组有语义的策略配置
4. **并发调度**：基于 1.3 节的调度架构，实现可靠的大规模采集
5. **数据管线**：实现 3.2 节的 JSON Lines 存储 + 完整性校验

**验收标准**：
- 单机吞吐量达到 100+ 局/秒（规则AI）
- 可复现性测试：同一 Seed 同一策略序列，10 次运行结果 100% 一致
- 所有 9 角色可独立配置出场
- 每个 Replay 记录包含 seed，可独立复现任意单局

### 6.3 2.1.0 阶段：Meta 分析管线

**策略绑定架构**：
- 初期：维持方案A，跑通全部分析流程
- 中期：为每个角色独立运行超参数优化（2.8 节贝叶斯优化）
- 末期：比较 $\Delta(c_i)$ 分布，评估方案C实施的必要性

**关键任务**：

1. **统计计算模块**：实现第四章的胜率矩阵、置信区间、假设检验、多重比较修正（Wilson 区间、双比例 Z 检验、Benjamini-Hochberg FDR）
2. **评级系统**：实现 Elo + Glicko 评级引擎，含 RD 置信度更新
3. **超参数优化器**：实现贝叶斯优化（GP + EI），支持对指定角色的 $\theta$ 独立优化
4. **报告生成器**：自动生成 Tier 报告 + 克制关系图数据

**验收标准**：
- 给定一批对局数据，可在 60s 内完成全部分析
- 输出包含：胜率矩阵、置信区间、效应量、Tier 报告、克制图
- 样本量自动推算工具（Power Analysis）
- 可为任一角色运行独立的超参数优化，输出最优 $\theta_i^*$ 及其置信区间

### 6.4 2.2.0 阶段：方案C 全量实施

**策略绑定架构**：切换至方案C，实现完整的双强度报告体系。

**触发条件**：2.1.0 阶段已完成，且以下条件中至少一项成立：
- 统计检测到部分角色的 $\Delta(c_i)$ 显著 > 50 Elo
- 规则 AI 无法有效区分角色差异（所有 $\hat{p}_{ij}$ 置信区间均包含 0.5）
- 需要为设计迭代提供更精确的强度参考

**关键任务**：

1. **全角色参数优化**：对 9 个角色各自运行超参数优化，构建 $\{\theta_1^*, \dots, \theta_9^*\}$
2. **双强度管线**：分别跑方案A（通用强度）和方案C（有效强度），输出对比报告
3. **操作天花板分析**：自动计算并标注 $\Delta(c_i)$，识别高潜力/低操作空间角色

**验收标准**：
- 9 角色的 $\theta_i^*$ 均附带收敛证明（GP 不确定性已稳定）
- 报告同时输出 $R_{base}(c_i)$ 和 $R_{effective}(c_i)$
- $\Delta(c_i)$ 置信区间通过 Bootstrap 计算并标注

### 6.5 2.2.0+ 阶段：策略进化（条件性启用）

**触发条件**：规则 AI 已无法有效区分角色差异（所有 $\hat{p}_{ij}$ 置信区间均包含 0.5），且 2.2.0 方案C已运行至少一轮。

**关键任务**：
