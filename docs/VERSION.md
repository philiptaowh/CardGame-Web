# 版本管理方案

## 版本格式

采用 **语义化版本 (SemVer)**：

```
主版本.次版本.修订号[-阶段标识]
```

| 组成部分                 | 变更条件                                               |
| ------------------------ | ------------------------------------------------------ |
| **主版本 (Major)** | 游戏模式重大变更（如从单机改为联机）、破坏性兼容性修改 |
| **次版本 (Minor)** | 新功能增加（如新增角色、新机制）、向后兼容的功能变更   |
| **修订号 (Patch)** | Bug修复、性能优化、小改进                              |

---

## 阶段标识

| 阶段         | 说明       | 使用场景       |
| ------------ | ---------- | -------------- |
| `alpha`    | 内部测试版 | 开发中，未对外 |
| `beta`     | 公开测试版 | 外部测试反馈   |
| `rc`       | 候选发布版 | 临近正式发布   |
| `(无标识)` | 正式版     | 稳定发布       |

## 版本号递增规则

1. **每次发布**必须更新版本号
2. **提交代码**时在 commit message 中标注版本号
3. **合并分支**时同步更新 CHANGELOG.md

## Git 操作参考

### 版本回溯

```bash
# 查看所有标签
git tag -l

# 切换到指定版本标签
git checkout v1.0.0

# 创建新标签
git tag -a v1.0.1 -m "Release version 1.0.1"

# 删除本地标签
git tag -d v1.0.0

# 删除远程标签
git push origin :refs/tags/v1.0.0
```

### 推送到 GitHub

```bash
# 添加远程仓库（首次）
git remote add origin https://github.com/<username>/<repo>.git

# 推送主分支
git push -u origin main

# 推送标签
git push origin v1.0.0

# 推送所有标签
git push origin --tags

# 强制推送到远程（慎用）
git push -f origin main
```
