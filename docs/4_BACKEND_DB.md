# 4_BACKEND_DB.md: 数据与后端规范

## 0. 适用说明

> **本文档记录本项目实际存在的服务端组件和数据层设计。**
>
> 本项目不是传统的后端项目，当前的服务端组件均为**非传统后端**——它们服务于特定场景而非通用 Web 后端：
>
> | 版本 | 组件 | 性质 | 技术选型 |
> |------|------|------|---------|
> | v1.2.x | WebSocket 游戏服务器 | 局域网联机的通信仲裁，无持久化，无数据库 | Electron 主进程内置 + `ws` 库 |
> | v2.x | 数据存储与分析层 | 仿真对局数据的采集、存储与聚合，仅开发工具使用，非面向用户 | JSON Lines + SQLite |
>
> **未来规划**：项目有上线网站、扩展为互联网联机的潜力，届时本文档将补充正式后端架构（认证、数据库、API 等）。详见第 3 节。

## 1. v1.2.x WebSocket 服务器

### 1.1 当前实现

| 组件 | 文件 | 职责 |
|------|------|------|
| WebSocket 服务器 | `electron/server.cjs` | 连接管理（join/leave/ready/start/消息广播）、心跳保活（ping/pong 30s, timeout 70s）、同步计时器、时间银行倒计时 |
| 游戏仲裁 | `electron/gameHost.cjs` | 服务端权威状态源，接收客户端操作指令，验证并执行游戏逻辑，广播同步状态 |
| 客户端通信 | `src/services/websocketService.ts` | 模块级 WebSocket 单例，自动重连，消息序列化/反序列化 |
| 通信协议 | `src/types/network.ts` | ClientMessage / ServerMessage 完整联合类型 |

### 1.2 架构特点

- **非传统后端**：服务器嵌入 Electron 主进程，无独立部署、无数据库、无持久化
- **单房间实例**：一个 Electron 进程 = 一个房间
- **有状态进程**：房间状态、玩家连接、时间银行均在内存中管理
- **系统托盘**：房主关闭窗口时服务器转入托盘后台运行

## 2. v2.x 数据存储架构

2.x 仿真分析平台在批量对局中产生大量结构化数据，需要可靠的存储体系。本层**仅供开发工具使用，不面向终端用户**。

### 2.1 数据流架构

```
仿真引擎 (ConcurrentRunner)
    │
    │ 每完成一局 → 输出 1 条 JSON Line
    ▼
data/raw/YYYY-MM-DD_batch-NNN.jsonl
    │
    │ Batch 完成后 → 批量导入
    ▼
data/db/winrate.db  (SQLite)
    │
    │ 分析引擎查询 → 生成报告
    ▼
Meta 分析输出 (Tier 报告 / 克制图 / 胜率矩阵)
```

### 2.2 存储目录规范

```
data/
├── raw/                         # 原始对局日志（JSON Lines）
│   ├── 2026-06-01_batch-001.jsonl
│   ├── 2026-06-01_batch-002.jsonl
│   └── ...
├── db/                          # 聚合数据库
│   └── winrate.db               # SQLite 聚合库
├── configs/                     # 实验配置
│   ├── strategy_pool.json       # 当前策略参数组
│   └── experiment_manifest.json # 实验清单（含种子、批次信息）
└── reports/                     # 生成的报告输出
```

### 2.3 数据格式

**原始日志**：JSON Lines（`.jsonl`），每行一条完整的对局 Replay 记录。

每条 JSON Line 的原子写入保证（单行长度 < 4KB 时文件系统保证原子性）：

```json
{
  "version": "1.0",
  "timestamp": 1717200000000,
  "duration": 45230,
  "seed": 20260601001,
  "config": {
    "policies": [
      { "playerId": "p1", "characterId": "char_3", "policyName": "aggressive", "policyParams": {...} },
      { "playerId": "p2", "characterId": "char_7", "policyName": "balanced", "policyParams": {...} }
    ]
  },
  "moves": [...],
  "winner": "p1",
  "finalState": { "turn": 15, "players": [...] },
  "stats": { "totalMoves": 42, "skillUsage": {...} }
}
```

### 2.4 数据完整性校验

每批次采集完成后执行：

1. **数量校验**：预期对局数 vs 实际记录数，偏差 ≤ 1%
2. **格式校验**：每条 JSON Line 可解析、字段完整、类型正确
3. **逻辑校验**：胜者标识有效、回合数 ≤ T_max、HP 非负
4. **种子复现采样**：随机抽取 0.1% 对局用记录的 seed 复现，验证结果一致
5. 校验不通过则该 Batch 标记为"不可信"，重新采集

### 2.5 非传统后端说明

- **无认证/授权**：数据仅本地生成、本地分析，无多用户访问需求
- **无数据库迁移**：SQLite 为仅追加写入，Schema 随代码版本控制
- **无持久化连接**：仿真器写入 → 分析器读取，无常驻进程
- **完全可丢弃**：`data/` 目录可由 `initGame()` 重新生成，不存在生产数据风险
